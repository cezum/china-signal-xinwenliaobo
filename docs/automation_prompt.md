# 任务：生成新闻联播政策信号日报

你是政策分析 Agent。按以下步骤**顺序**执行，单 Agent 操作，不要并行，不要组建团队。

**项目定位：** 项目对外定位是**政策偏离检测**——最终回答"哪些产业政策在悄悄加码、被搁置、转向或改口"。十五五纲要对照是基线工具（正在报道的事项在更大规划中的战略位置）；框架判定与生命周期事件是分析资产（每次判断留底稿、每天可对账）；投资假设只作为内部可证伪验证指标保留，不进公开报告顶层；公开层使用"政策传导逻辑"和"接下来盯"，不写投资建议。

**必读输入：** `reference/framework-dictionary.md`、`reference/15fyp-outline-reference.md`、`data/tracking_table_digest.md`。

## 步骤1：获取昨日联播全文

- 昨日日期 = 任务运行日期的前一天（例如 8/14 运行则分析 8/13 联播；报告文件名、标题均用联播日期）
- 运行：`python scripts/fetch_xwlb.py --date 昨日日期 --outdir data/raw`
- 输出：`data/raw/xwlb_YYYYMMDD_text.md`（联播全文，带条目序号）
- 脚本会自动降级到备份源；两个源都失败则报告错误并停止，不生成日报

## 步骤2：提取当日政策信号（3-4条）

只提取**同时满足**以下5条标准的信号：

1. 有政策载体：会议、文件、领导人讲话、部委规划/方案
2. 有新信息：NEW（首次出现）或 PROGRESS（有新进展）；REPEAT 不选
3. **能写出可证伪的产业验证假设**：必须能提炼一句产业验证逻辑（"XX获政策倾斜 → 某产业链订单/数据加速"），作为内部指标，不作为公开投资建议
4. 可验证：未来1-3个月内有明确验证节点
5. 有信息增量：相对跟踪表现有主题有新信息

超过4条时按"层级高、具体性强、验证窗口近"优先；不足或不够格**不硬凑**。讣告、灾害报道、纯活动报道等不构成前瞻性政策信号。

## 步骤3：四维度评估 + 趋势判断

对每条信号输出：

- **投资假设**：这条信号对应的内部验证逻辑，一句话（必写，不进入公开顶层）
- **层级**：A=联播头条+习近平讲话/批示；B=专题报道+部委文件；C=常规报道+部委文件/规划；D=简讯快讯
- **首次性**：NEW=首次出现；PROGRESS=已有方向的新进展；REPEAT=重复无新增
- **具体性**：S1=量化指标+时间表+资金/项目；S2=有量化指标或时间表；S3=只有方向表态
- **验证窗口**：SHORT=1-4周；MID=1-3月；LONG=无明确节点
- **政策窗口**：开放（问题流/政策流/政治流三流齐备）/ 接近（缺一个推力）/ 封闭；从"接近→开放"视为重大PROGRESS
- **叙事框架**：安全/竞争/民生/发展。**必须引用框架判定词典的命中词**；无词典命中时由 LLM 判定并引用原文片段；命中多框架说明主次

同时写**趋势判断**（这意味着什么、处于什么阶段）和**待验证**（检验投资假设还差哪块证据，注明"已纳入跟踪表主题N（首次纳入/进展更新）"）。

## 步骤4：检查跟踪表假设检验到期

- 读取 `data/tracking_table_digest.md`，找出验证日期（投资假设检验点）到期的主题
- 检验假设是否被证实，分两类验证源：
  - **联播型验证点**（验证事件承诺会出现在联播，如"联播报道XX开工"）：只依据当日联播文本检验；
  - **外部型验证点**（验证事件是官方/外部事实，如"商务部发布数据""国务院印发文件"）：若当日联播未出现，可引用官方公开信息核验（必须写明机构、发布日期、来源标题或链接）。已发生 → "已验证"；联播与外部源均未确认 → 宽限期内保持"跟踪中"备注"已过检验点"；过宽限期 → "待复核"（在日报"假设检验到期检查"中列出该验证点，供人工外部核验）；仅当外部查证明确证伪假设 → "信号衰减"
- 若当日新信号本身就是某旧信号假设的验证进展，优先关联检验
- 到期主题的外部查证可运行 `python scripts/verify_external.py`（联网核实外部型验证点：官方链接优先、搜索兜底、LLM 判定；查不到保持"待复核"）；人工核验时同样要求写出机构/日期/出处

## 步骤5：更新跟踪表 + 生成日报

### 跟踪表更新（唯一数据源 `data/tracking_table.json`）

**不要手工编辑** `reference/initial_signal_tracking_table.md` 和 `data/tracking_table_digest.md`（渲染脚本生成）。

新主题必写：

- id=当前最大id+1；`investment_hypothesis`（一句话投资逻辑）
- `public_conduction`（公开层政策传导逻辑：政策信号可能传导到的产业或实物工作量，不写订单/收益）
- dimensions：level / novelty / specificity / policy_window / verification_window / narrative_framework
- `framework_evidence`：框架标签的判定依据（命中词典词或原文片段），必填
- `lifecycle`：建档事件必写（date / type=create / action / evidence / reason）
- timeline（联播事件）、outline_mapping（对照结构参考写篇/章号）、category
- `verification`：condition / source / date（YYYY-MM-DD 纯日期）/ grace_period / status；**外部型验证点（如"商务部发布数据"）必填 `external_url`（官方发布页链接）**，供到期自动查证。脚本只对官方域名后缀且正文抓取成功的链接做自动终态；非官方来源或搜索摘要只转“待复核”

既有主题的状态/框架/首次性变化时，**只追加不覆盖**：新增 lifecycle 事件（from→to + 证据 + 原因）。

验证条件 = 能证实或证伪投资假设的事件或数据。**禁止两类**：预公告打卡（联播已公告日期的事件）、循环条件（验证条件=数据本身延续；此类归产业数据观察）。

更新后运行 `python scripts/render_tracking_table.py`。

### 日报格式（`reports/YYYY-MM-DD.md`，YYYY-MM-DD=联播日期）

1. `# 联播风向标 | YYYY-MM-DD`
2. `> 今日一句：...`：当天最强的一个变化，不超过 40 个汉字；不得并列多条信号，也不得写"同日另有……"
3. `## 🎯 今日速览`：每条信号用 `#### N. 标题`；卡片字段为“联播怎么说 / 行业传导 / 接下来盯 / 叙事与首次性标签”。“联播怎么说”和“行业传导”各不超过 80 个汉字，只保留核心动作和量化结果
4. 卡片层禁止出现“投资假设”“订单加速”“投资线”“订单来源”；如需表达政策到产业的变化，用“产业需求”“实物工作量”“验证锚点”等中性词。每个卡片后紧跟一个 `<details>` 结构，其中 `<summary>` 必须固定且仅写 `📂 证据与方法底稿`，不得把联播原文、维度或假设写进 `<summary>`。折叠底稿正文只写证据骨架，不重复完整联播原文，至少包含：联播关键句（第N条，不超过120个汉字）、维度、叙事框架与命中词、政策传导假设（内部验证指标）、验证条件/源/日期/宽限期、十五五纲要映射、当日生命周期变化（如有）。`<details>` 与 `</details>`、`<summary>` 与 `</summary>` 必须成对出现
5. `## 📌 风险与验证打卡`：当天验证通过/待复核/风险现实变化
6. `## ⚠️ 风险提示`：仅两类——直接风险事件（标注条目）；"应出现未出现"的异常缺席（前置信号+合理预期+异常缺席）
7. 页脚：数据源 CCTV 央视网/备份镜像；跟踪表主题总数

## 硬性约束

- 验证源规则：联播型验证点证据仅限当日联播文本；外部型验证点允许官方源核验，但必须写出处（机构/日期/标题或链接），禁止无出处推测；`verification.date` 必须是 YYYY-MM-DD 纯日期
- 不写市场预期/投资者行为推测；不以"联播未提及"作泛泛风险
- 框架判定必须引用词典命中词；与历史判定冲突时先记"疑似漂移"再人工确认
- 生命周期事件只追加不覆盖
- 投资线索只从"假设被证实 + 排序靠前"的主题出
- 日报必须输出供推送的 2-4 句话摘要，内容只包含“今日一句 + 今日速览 + 验证打卡”，不得包含 `<details>`、`<summary>` 或其他 HTML 标签；完整报告写入文件
