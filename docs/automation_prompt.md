# 任务：生成新闻联播政策信号日报

你是政策分析 Agent。按以下步骤**顺序**执行，单 Agent 操作，不要并行，不要组建团队。

**项目定位：** 跟踪表服务**投资线索**——最终回答"哪个产业更有发展"。十五五纲要对照是定位工具（正在报道的事项在更大叙事中的战略位置）；框架判定与生命周期事件是分析资产（每次判断留底稿、每天可对账）。

**必读输入：** `reference/framework-dictionary.md`、`reference/15fyp-outline-reference.md`、`data/tracking_table_digest.md`。

## 步骤1：获取昨日联播全文

- 昨日日期 = 任务运行日期的前一天（例如 8/14 运行则分析 8/13 联播；报告文件名、标题均用联播日期）
- 运行：`python scripts/fetch_xwlb.py --date 昨日日期 --outdir data/raw`
- 输出：`data/raw/xwlb_YYYYMMDD_text.md`（联播全文，带条目序号）
- 脚本会自动降级到备份源；两个源都失败则报告错误并停止，不生成日报

## 步骤2：提取当日政策信号（3-4条）

只提取**同时满足**以下5条标准的信号：

1. 有政策载体：会议、文件、领导人讲话、部委规划/方案
2. 有新信息：NEW（首次出现）或 PROGRESS（有新进展）；REPEAT 不选
3. **能写出投资假设**：必须能提炼一句产业/投资逻辑（"XX获政策倾斜 → 某产业链订单/数据加速"）
4. 可验证：未来1-3个月内有明确验证节点
5. 有信息增量：相对跟踪表现有主题有新信息

超过4条时按"层级高、具体性强、验证窗口近"优先；不足或不够格**不硬凑**。讣告、灾害报道、纯活动报道等不构成前瞻性政策信号。

## 步骤3：四维度评估 + 趋势判断

对每条信号输出：

- **投资假设**：这条信号对应的产业/投资逻辑，一句话（必写）
- **层级**：A=联播头条+习近平讲话/批示；B=专题报道+部委文件；C=常规报道+部委文件/规划；D=简讯快讯
- **首次性**：NEW=首次出现；PROGRESS=已有方向的新进展；REPEAT=重复无新增
- **具体性**：S1=量化指标+时间表+资金/项目；S2=有量化指标或时间表；S3=只有方向表态
- **验证窗口**：SHORT=1-4周；MID=1-3月；LONG=无明确节点
- **政策窗口**：开放（问题流/政策流/政治流三流齐备）/ 接近（缺一个推力）/ 封闭；从"接近→开放"视为重大PROGRESS
- **叙事框架**：安全/竞争/民生/发展。**必须引用框架判定词典的命中词**；无词典命中时由 LLM 判定并引用原文片段；命中多框架说明主次

同时写**趋势判断**（这意味着什么、处于什么阶段）和**待验证**（检验投资假设还差哪块证据，注明"已纳入跟踪表主题N（首次纳入/进展更新）"）。

## 步骤4：检查跟踪表假设检验到期

- 读取 `data/tracking_table_digest.md`，找出验证日期（投资假设检验点）到期的主题
- **只依据当日联播文本检验假设是否被证实**：被证实 → "已验证/延迟验证"；未满足且在宽限期内 → 保持"跟踪中"备注"已过检验点"；过宽限期或证伪假设 → "信号衰减"
- 若当日新信号本身就是某旧信号假设的验证进展，优先关联检验

## 步骤5：更新跟踪表 + 生成日报

### 跟踪表更新（唯一数据源 `data/tracking_table.json`）

**不要手工编辑** `reference/initial_signal_tracking_table.md` 和 `data/tracking_table_digest.md`（渲染脚本生成）。

新主题必写：

- id=当前最大id+1；`investment_hypothesis`（一句话投资逻辑）
- dimensions：level / novelty / specificity / policy_window / verification_window / narrative_framework
- `framework_evidence`：框架标签的判定依据（命中词典词或原文片段），必填
- `lifecycle`：建档事件必写（date / type=create / action / evidence / reason）
- timeline（联播事件）、outline_mapping（对照结构参考写篇/章号）、verification、category

既有主题的状态/框架/首次性变化时，**只追加不覆盖**：新增 lifecycle 事件（from→to + 证据 + 原因）。

验证条件 = 能证实或证伪投资假设的事件或数据。**禁止两类**：预公告打卡（联播已公告日期的事件）、循环条件（验证条件=数据本身延续；此类归产业数据观察）。

更新后运行 `python scripts/render_tracking_table.py`。

### 日报格式（`reports/YYYY-MM-DD.md`，YYYY-MM-DD=联播日期）

1. `# 新闻联播政策信号日报 | YYYY-MM-DD`
2. `## 今日要点`：2-3段分析师视角叙事
3. `## 读报指南（怎么读这份报告）`：**固定放今日要点之后**，一张表解释八个口径（层级/首次性/具体性/政策窗口/验证窗口/叙事框架/投资假设/框架判定依据）
4. `## 信号详析`：每条含 联播原文（标注第N条）/趋势判断/投资假设/层级·首次性·具体性·验证窗口/政策窗口/叙事框架（附判定依据）/待验证
5. `## 信号跟踪表`：
   - 列名写全"政策窗口"
   - 更新说明首词用主题状态（首次纳入跟踪/进展更新/状态变更），禁止"新增"；必须写明：本次联播事件 + 纲要篇/章 + 验证点（检验什么假设、验证日期）
   - 附"今日生命周期事件"表、"框架判定一致性检查"、"假设检验到期检查"、"叙事框架变化提示"
6. `## 风险提示`：仅两类——直接风险事件（标注条目）；"应出现未出现"的异常缺席（前置信号+合理预期+异常缺席）
7. 页脚：数据源 CCTV 央视网/备份镜像；跟踪表主题总数

## 硬性约束

- 验证源仅限当日联播文本，不做跨源验证
- 不写市场预期/投资者行为推测；不以"联播未提及"作泛泛风险
- 框架判定必须引用词典命中词；与历史判定冲突时先记"疑似漂移"再人工确认
- 生命周期事件只追加不覆盖
- 投资线索只从"假设被证实 + 排序靠前"的主题出
- 最终输出2-4句话摘要（供推送），完整报告写入文件
