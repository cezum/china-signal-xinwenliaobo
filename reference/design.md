# 新闻联播政策分析项目重构方案

**版本：v2.0 | 制定日期：2026-08-12**

---

> **2026-08-16 定位确认：** 本项目对外定位已从“投资线索工具”切换为“政策偏离检测”。跟踪表最终回答“哪些产业政策在悄悄加码、被搁置、转向或改口”，核心结构为“规划承诺 → 联播叙事 → 现实兑现”三层对照。下文中的“投资假设/投资线索”均作为内部可证伪验证指标保留；公开层统一展示为“政策传导逻辑”和“可跟踪线索”。

## 一、重构背景

### 1.1 旧方案问题（v1.0）

| 问题 | 具体表现 | 根因 |
|------|---------|------|
| 内容重复 | 同一条新闻在 Part 1.1/1.2/1.4/2.2/3.1 反复出现 | Part 1/2/3 平行割裂，按时间线而非主题组织 |
| 表格驱动 | 大量表格制造"信息丰富"假象，实际只是分类不是洞察 | 追求格式完整而非分析深度 |
| 缺乏深度 | 复述联播原文多，"这意味着什么"的判断少 | 没有区分"事实提取"和"趋势判断"两个层级 |
| 无增量价值 | 读完报告获得的信息≈读联播原文 | 没有跟踪机制，无法积累信号演进脉络 |
| 自动化失败 | 4人Agent团队消耗大量context，导致执行中断 | 架构过重，超出自动化模式承载能力 |

### 1.2 重构目标

将报告从**"每日全覆盖信息摘要"**重构为**"政策趋势雷达 + 信号跟踪闭环"**：

- 每天只做两件事：提取政策信号、判断趋势方向
- 持续跟踪信号演进，积累到足够强度才出投资线索
- 通过回溯验证形成反馈闭环，持续提升判断质量

## 三、信号提取与评估框架

### 3.1 信号提取标准

不是每条新闻都值得成为"政策信号"。提取时必须同时满足以下标准：

| 标准 | 要求 | 反例（不提取） |
|------|------|---------------|
| 有政策载体 | 必须是会议、文件、领导人讲话、部委规划/方案 | 单纯的灾害报道、国际新闻、社会新闻 |
| 有新信息 | 必须是 NEW（首次出现）或 PROGRESS（有新进展），REPEAT 不选 | "持续推动高质量发展"等重复表述 |
| 能写出投资假设 | 必须能提炼一句产业/投资逻辑（"XX获政策倾斜 → 某产业链订单/数据加速"） | 文化交流、人物报道、纯民生服务 |
| 可验证 | 必须能在未来 1-3 个月内找到具体验证节点 | 过于宏大、无法追踪的远景表述 |
| 有信息增量 | 相对于跟踪表中的已有信号，必须提供新信息 | 与已有跟踪信号重复的日常进展 |

**每日上限：3-4 条。** 超过 4 条时，按"层级高、具体性强、验证窗口近"优先选取。

**提取方式：** 由 LLM 按上述标准输出结构化结果，格式如下：

```json
{
  "signals": [
    {
      "title": "信号名称",
      "source_text": "联播原文摘要，标注具体新闻条目",
      "reason": "为什么这条符合提取标准",
      "hypothesis": "投资/产业逻辑一句话（如：核电安全化 → 核电设备订单加速）",
      "level": "A/B/C/D",
      "novelty": "NEW/PROGRESS/REPEAT",
      "specificity": "S1/S2/S3",
      "verification_window": "SHORT/MID/LONG",
      "verification_condition": "具体可验证事件",
      "verification_source": "联播"
    }
  ]
}
```

如果 LLM 提取的结果不符合上述标准，直接 discard，不硬凑。

### 3.3 四维度评估

每个政策信号用四个维度评估，不合并为总分：

**维度一：政策层级（谁在说）**

| 信号特征 | 等级 | 说明 |
|---------|------|------|
| 联播头条 + 习近平讲话/批示 | A | 最高层级释放 |
| 联播专题报道 + 部委文件 | B | 经最高层定调后部门落地 |
| 联播常规报道 + 部委文件/规划 | C | 部委自主发布 |
| 联播简讯/快讯 | D | 信息告知，政策意图弱 |

**维度二：首次性（是不是新信号）**

| 信号特征 | 标签 | 说明 |
|---------|------|------|
| 首次提出某政策方向/首次有文件落地 | NEW | 全新信号，建立跟踪 |
| 之前提过方向，这次有新进展 | PROGRESS | 信号升级，趋势在推进 |
| 重复报道已有内容，无新增信息 | REPEAT | 信号衰减，无跟踪价值 |

**维度三：具体性（有没有抓手）**

| 信号特征 | 等级 | 说明 |
|---------|------|------|
| 有量化指标 + 时间表 + 资金/项目落地 | S1 | 最具体，可直接追踪 |
| 有量化指标或时间表，无资金/项目 | S2 | 方向明确，等落地细节 |
| 只有方向性表述 | S3 | 最模糊，无法追踪 |

**维度四：可验证窗口（多久能看到后续）**

| 信号特征 | 标签 | 说明 |
|---------|------|------|
| 1-4周内有明确验证节点 | SHORT | 近期可验证 |
| 1-3个月内有验证节点 | MID | 中期可验证 |
| 无明确验证节点 | LONG | 长期观察 |

### 3.4 为什么不合并总分

不同维度的组合代表不同的行动含义，合并会丢失信息：

- **B + NEW + S1 + SHORT** = 最值得立即关注
- **B + PROGRESS + S3 + LONG** = 趋势确认但无行动抓手
- **C + NEW + S2 + MID** = 有价值但不紧急
- **A + REPEAT + S3 + LONG** = 信号已消化

用户结合自身市场感知（板块热度、资金关注、技术面位置）做最终判断。

### 3.5 政策窗口状态（Policy Windows）

基于 Kingdon 多源流理论：政策突破需要三个"流"同时汇合。跟踪表中为每个主题增加窗口判断，用于预测政策从"方向"到"落地"的推进概率。

**三个流的判断标准：**

| 流 | 判断标准 | 激活标志 |
|----|---------|---------|
| 问题流 | 该议题是否被定义为"必须解决的问题" | 联播出现事故/危机/困难报道、领导人就此作出批示、出现相关负面经济数据 |
| 政策流 | 是否有现成的解决方案在推进 | 已有试点、已出台征求意见稿、相关部委已在制定细则 |
| 政治流 | 高层关注度 + 政治时机是否对齐 | 进入政治局/国务院常务会议程、领导人重要讲话提及、在关键时间节点（两会/全会）前后 |

**窗口状态：**
- **开放**：三流同时激活 → 短期内大概率出具体细则/文件
- **接近**：二流激活 → 方向明确但缺某个推力
- **封闭**：零或一流激活 → 停留在表态阶段

**日报中的使用：** 提取信号时判断所属主题的窗口变化（从接近→开放视为重大PROGRESS），在信号详析中注明。
日报跟踪表的列名必须写全"政策窗口"，不得简写为"窗口"（与"验证窗口"区分）；表下须附一行通俗解释（开放=三流齐备短期出细则概率高，接近=差一个推力，封闭=暂不具备条件）。

### 3.6 叙事框架标签（Narrative Framing）

同一个政策方向，联播用什么叙事框架，决定了其执行优先级和资源分配逻辑。

| 框架 | 关键词 | 力度预期 | 典型案例 |
|------|--------|---------|---------|
| 安全框架 | "牢牢守住""底线""安全""自主可控" | 最高优先级，不计成本 | 粮食安全、能源安全、科技自主可控 |
| 竞争框架 | "抢占""引领""制高点""话语权" | 高优先级，资源倾斜 | AI治理、标准制定、未来产业 |
| 民生框架 | "兜底""保障""获得感""均等化" | 中优先级，稳步推进 | 长护险、公共服务均等化 |
| 发展框架 | "培育""壮大""新动能""激发" | 市场化推进 | 服务业扩能、消费升级 |

**使用规则：**
- 每条信号标注叙事框架标签
- 同一主题如果框架发生迁移（如 AI 从"竞争框架"→"安全框架"），这是比层级提升更强的信号，必须在日报中重点讨论
- 跟踪表中增加"叙事框架"字段，每次更新时如框架变化则更新
- **判定标准化（2026-08-13 起）**：框架判定执行"词典为主、LLM 兜底、依据必填、冲突告警"。词典见 `reference/framework-dictionary.md`；每条判定必须写 `framework_evidence`（命中词或原文片段）；无依据 = 待补证；新判定与历史判定冲突时，区分"叙事真变（记框架变更事件）"与"疑似漂移（人工确认）"

### 3.7 报告可读性要求（2026-08-13 起执行，2026-08-17 起改为双层结构）

目标读者：政策研究者 + 大学教育背景的非专业人士。所有评估口径必须能在日报内自行读懂，不依赖外部文档。

- 日报不再每日重复“读报指南（术语表）”，改为“今日一句 + 🎯 今日速览 + 📌 验证打卡”的极简层；术语表移入 `notes/如何看懂这份雷达.md`
- 每个速览卡片后必须带 `<details>` 证据底稿，至少包含联播原文、维度、框架命中词、投资假设、验证条件与十五五纲要映射
- 跟踪表列名写全"政策窗口"，不简写"窗口"
- 每条信号/主题呈现必须带"十五五纲要映射"（日报跟踪表更新说明 + 完整跟踪表字段），章节引用以 `reference/15fyp-outline-reference.md` 为准
- 更新说明区分"主题状态"与"信号首次性"，不得以"新增"代替"首次纳入跟踪"

## 四、信号跟踪与回溯验证

### 4.1 滚动跟踪表设计

每天日报末尾附带滚动跟踪表，持续更新：

| 政策信号 | 投资假设 | 首次出现 | 最新进展 | 层级 | 首次性 | 具体性 | 政策窗口 | 叙事框架 | 检验条件 | 验证源 | 验证日期 | 宽限期 | 状态 |
|---------|---------|---------|---------|------|--------|--------|---------|---------|---------|--------|---------|--------|------|
| 示例：长护险全国推行 | 长护险全面推行 → 护理/康复产业链市场规模扩大 | 8/11联播 | 中办国办文件已发 | B | PROGRESS | S2 | 开放 | 民生框架 | 联播报道长护险配套文件出台或参保数据公布 | 联播 | 9/11 | 10/11 | 跟踪中 |
| 示例：煤炭十五五规划 | 煤炭现代化升级 → 煤机/智能化设备订单 | 8/11联播 | 规划已发布 | C | NEW | S1 | 接近 | 安全框架 | 联播后续报道省级执行方案出台 | 联播 | 11/11 | 12/11 | 跟踪中 |

### 4.2 投资假设与检验条件编写规范

每个主题建档时写一句**投资假设**（格式："XX获政策倾斜 → 某产业链订单/数据加速"），验证机制全部围绕这句假设设计：

- **假设必须可证伪**：检验条件要写成能证实或证伪该假设的具体事件或数据，不能是"有进展"这种模糊判断
- **验证点分两类**：
  - **联播型**：检验事件承诺会出现在联播（如"联播报道XX开工"），证据仅限当日联播原文；
  - **外部型**：检验事件是官方/外部事实（如"商务部发布数据""国务院印发文件"），联播未报道时允许官方源核验，但必须写明机构、发布日期与来源标题/链接，禁止无出处推测
- **单一信源局限（2026-08-16 修订）**：仅用联播判断外部事件会漏掉"已发生但未上联播"的事实（实例：商务部 7/23 已发布上半年外资数据，而 8/15 联播未报道）。外部型验证点到期时，"联播无信号"只说明"联播未报道"，不等于"事实未发生"

**禁止两类检验条件：**
1. **预公告打卡**：联播已公告日期的事件（如"9月通航"）不设验证日期，属于零信息量打卡；应改为检验事件之后的经济结果（如货运量、沿线产业布局）
2. **循环条件**：检验条件不能就是假设结论本身的数据延续（如"出口数据是否延续"是趋势检验而非政策验证，此类主题归入产业数据观察，不占政策验证额度）

### 4.3 状态流转规则

```
跟踪中 → 已验证（投资假设被检验条件证实：联播型看联播原文，外部型可官方源核验）
跟踪中 → 延迟验证（验证日期过后、宽限期内满足）
跟踪中 → 待复核（宽限期过后联播仍无验证信号：转人工外部核验，不自动判衰减）
待复核 → 已验证（外部查证证实）/ 信号衰减（外部查证证伪）
已验证 → 投资线索就绪（假设被证实+用户判断值得深入）
信号衰减 → 归档（移出跟踪表，记录失败原因）
```

### 4.4 每日假设检验检查

自动化执行时，检查跟踪表中是否有假设检验点到期（验证日期到达）：
- 检验点到达 → 分两类检查：
  - **联播型验证点**：检查当日联播文本是否出现检验条件中的事件；
  - **外部型验证点**：当日联播无信号时，用官方公开信息核验（写明机构/日期/出处）；无法自动核验时标记"待复核"交人工外部查证
- 出现/核验证实 → 状态改为"已验证"或"延迟验证"
- 未确认且在宽限期内 → 保持"跟踪中"，备注"已过检验点"
- 宽限期过后仍未确认 → 状态改为"待复核"（不自动判衰减）；仅当外部查证明确证伪假设 → "信号衰减"

**2026-08-16 修订**：原"信息源仅限当日联播文本"规则对外部事件型验证点会产生假阴性——事件已发生而联播未报道时，系统误判"未验证"（实例：商务部 7/23 发布上半年外资数据，8/15 检验点联播未报道，实际早已发布）。因此验证源改为"联播型/外部型"两类，宽限期后的自动流转只到"待复核"，终判交人工或外部查证。

### 4.5 日报跟踪表"更新说明"写作规范（2026-08-13 起执行）

1. 更新说明首词表达**主题状态**：首次纳入跟踪 / 进展更新 / 状态变更（已验证、延迟验证、信号衰减、归档），不用"新增"二字概括
2. 首次纳入跟踪 ≠ 政策方向新增：大多数主题是"十五五"纲要既有部署的落地或见效，更新说明必须写明"本次联播发生了什么 + 对应纲要哪一篇哪一章"
3. "首次性"列（NEW/PROGRESS/REPEAT）表达信号性质，与主题状态是两回事，两者不得混写
4. 纲要章节引用一律以 `reference/15fyp-outline-reference.md` 为准，不得凭记忆写篇/章号
5. 新主题建档必须写"投资假设"；**更新说明必须写明该主题的验证点**（检验什么假设、验证日期，如"验证点：新项目开工/核能综合利用落地（检验安全化叙事是否兑现为订单起点）"）

### 4.6 议题生命周期事件规范（2026-08-13 起执行）

每个主题维护一张**生命周期事件表**（tracking_table.json 的 `lifecycle` 字段），记录"分析模型发生了什么、为什么"——与 timeline（联播发生了什么）区分：

- **事件类型**：建档（create）/ 框架变更（framework_change）/ 状态流转（status_change）/ 首次性更新（novelty_change）/ 验证（verify）/ 衰减（decay）/ 进展更新（update）
- **必填字段**：日期、类型、动作（from→to）、证据（引用联播条目或原文片段）、原因（决策理由）
- **只追加不覆盖**：任何状态/框架/首次性变化只能新增事件，不能改写历史
- **机器可校验**：证据引用的联播条目应存在、状态流转应符合 4.3、框架标签应命中词典（否则进"待补证/疑似漂移"清单）
- 渲染产物：reference/initial_signal_tracking_table.md 每个主题增加"生命周期事件"表；完整跟踪表增加"框架判定一致性检查"段

## 五、自动化执行流程

### 5.1 流程简化

旧方案：4人Agent团队并行 → 汇总 → 报告（context消耗极大）

新方案：单Agent顺序执行，分5步：

```
步骤1：获取当日联播全文（运行 scripts/fetch_xwlb.py，主源 CCTV 央视网、备份 mrxwlb.com，输出 xwlb_YYYYMMDD_text.md）
步骤2：提取当日政策信号（基于联播文本，按筛选标准选出3-4条）
步骤3：对每条信号做四维度评估 + 趋势判断
步骤4：检查跟踪表假设检验到期（读取跟踪表，仅用当日联播文本检验投资假设是否被证实）
步骤5：更新跟踪表 + 生成日报
```

**顺序说明：** 检查到期信号放在步骤4，是因为当日新信号可能就是某个旧信号的验证进展。必须先完成当日信号分析，再回头检查跟踪表中哪些预设条件已被满足或超时。

### 5.2 Context优化措施

| 措施 | 效果 |
|------|------|
| 去掉4人Agent团队 | 节省Agent调度开销约40% |
| 去掉同比分析（不每天拉历史数据） | 节省约30% context |
| 去掉十五五纲要全文对比（只用结构参考） | 节省约15% |
| 精选3-4条而非全覆盖 | 减少输出长度 |
| 预计总context | 从55,000+降至25,000-30,000 |

### 5.3 自动化配置调整建议

待项目调整完成后执行：
- 模型：优先指定大上下文窗口的模型，避免长 prompt 中途截断
- 推理：开启模型的思考模式，提升信号评估质量
- Prompt：精简为单 Agent 顺序执行（见 docs/automation_prompt.md）

## 六、投资线索专题（不定期）

### 6.1 触发条件

当且仅当以下条件同时满足时，单独生成投资线索专题：
1. 跟踪表中某主题的投资假设被证实（状态变为"已验证"）
2. 用户判断该信号值得深入（人工触发）

### 6.2 专题内容

- 政策信号回顾（从首次出现到验证通过的完整脉络）
- 产业链受益逻辑（按确定性分层）
- 后续验证节点（下一阶段需要关注什么）
- 不包含：个股推荐、买卖建议（超出联播分析能力边界）

### 6.3 周期性回顾

- **周报**（每周日）：本周信号演化速览——本周新增几条、验证通过几条、延迟/衰减几条；哪些主题热度升温（本周高频出现）、哪些热度回落（本周静默）；下周到期的验证节点预告。**不做去年同期对比**（十五五开局阶段缺少可比的同期参照，内部演进比外部对比更有信息量）。
- **月报**（每月末）：信号跟踪表大盘点，统计验证命中率，回顾判断准确性。月末可做一次十五五纲要覆盖度热力图（哪些篇章被高频提及，哪些至今静默）。

## 七、风险提示规范（修订）

### 7.1 两类内容

**第一类：联播文本中的直接风险事件**

必须是新闻联播明确报道的负面信号，包括：
- 自然灾害（台风、洪水、地震、极端天气）
- 安全事故（生产安全、交通安全、公共卫生）
- 地缘冲突升级或国际紧张局势
- 经济数据中的负面表述
- 政策执行中的困难、挑战或风险表述

每条必须标注具体新闻条目来源，能回答"这是联播哪条新闻说的？"。

**第二类："应出现未出现"的异常缺席信号**

不是泛泛的"联播没提XX"，而是必须同时满足：
1. **有明确前置信号**：此前已经确定某事会在今天/近期发生
2. **有合理出现预期**：比如重要会议按惯例应报道、某项政策按此前时间表应出台
3. **缺席确实异常**：打破常规或打破预期的缺席，而非日常性沉默

每条必须说明"此前预期是什么"以及"为什么今天应该出现"。

**示例：**
- ✅ 合格："国家发改委此前预告8月上旬公布《XXX办法》，按惯例应在近期联播报道进展，但今日未提及"（前置信号+合理预期+异常缺席）
- ❌ 不合格："今日联播未提及中美关系"（日常沉默，不构成风险）

### 7.2 禁止内容

- 对市场预期的推测
- 对市场心理的判断
- 对投资者行为的预测
- 以"联播未提及"为由的泛泛风险判断
- 任何无法从新闻联播文本或已公开时间表中找到依据的主观判断

## 九、与旧方案的关键差异总结

一句话：**从"每天出一份全覆盖信息摘要"改为"每天做政策趋势雷达扫描 + 持续跟踪信号演进到可验证"。**

核心变化：
1. **少即是多**：从全覆盖26条改为精选3-4条，每条写透
2. **叙事替代表格**：从8-10个表格改为分析段落+1个跟踪表
3. **跟踪闭环**：新增信号跟踪表 + 回溯验证机制，让每个预判可检验
4. **投资线索后置**：从每天硬凑改为信号累积够强才单独出
5. **执行轻量化**：从4人Agent并行改为单Agent顺序执行，降低context消耗
